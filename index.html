The Core Insight

Attention scoring is mathematically identical to inner-product similarity search in vector databases.

Attention = Vector Retrieval
Attention computes q·kℓ for all keys and ranks them via softmax. Vector databases solve this exact problem at 100× compression using asymmetric distance computation (ADC): queries stay in full precision, database vectors remain compressed, and distances are computed via lookup tables—no decompression ever occurs.
Why Rank Correlation Matters
Softmax only requires preserving the relative ordering of attention scores, not their exact values. ADC maintains rank correlation ρ > 0.99 at 100× compression. If q·k1 > q·k2 in the original, it remains true in the approximation. That's all attention needs.

Codebook Learning
K-Means clustering learns 256 prototype patterns per subspace from calibration data. Each 16D chunk is replaced by the index (0-255) of its nearest centroid. Total storage: 4 subspaces × 256 centroids × 16 dims × 2 bytes = 32KB per layer.

When Should You Use LOOKAT?

✓ Ideal Use Cases

  • Edge device deployment (phones, embedded systems)
  • Bandwidth-constrained environments (~50 GB/s)
  • Post-training compression (no retraining available)
  • Long-context inference (512+ tokens)
  • Memory-bound inference scenarios
  • Need >16× compression ratios

✗ Not Recommended

  • High-bandwidth datacenter GPUs (>1 TB/s)
  • Tasks requiring exact numerical precision
  • Very short sequences (<64 tokens)
  • When INT8 quality is already insufficient
  • Scenarios where 8× compression is adequate
Implementation Requirements
Drop-in replacement for standard attention—no architecture changes required. One-time codebook learning via K-Means on calibration data (a few hundred samples). 32KB codebook storage per layer. No training or fine-tuning needed. Compatible with existing transformer implementations.
